# Esquema PostgreSQL inicial

## Estado em 29/07/2026

A migracao `0001_schema_inicial.sql` foi aplicada somente no banco
`endemias_teste`.

Este era o estado inicial em 29/07. Em 31/07/2026, a mesma migracao foi aplicada
em `endemias_migracao` e recebeu a carga integrada descrita em
`docs/POSTGRESQL_CARGA_TESTE.md`. Em 03/08/2026, ela tambem foi aplicada no
banco final `endemias`, que recebeu a carga preliminar validada. Ainda em
03/08/2026, a carga final foi aplicada e PostgreSQL passou a ser o backend de
producao; o `endemias.db` ficou congelado como rollback.

Nenhuma linha de negocio foi copiada na etapa de criacao do esquema. A etapa
seguinte carregou e validou os dados conforme
`docs/POSTGRESQL_CARGA_TESTE.md`.

## Diferencas intencionais

- Identificadores foram normalizados para minusculas. Isso evita problemas com
  nomes PostgreSQL sensiveis a maiusculas quando delimitados. As colunas
  SQLite `SISPNCD` e `CONTAOVOS_STATUS` passaram a `sispncd` e
  `contaovos_status`.
- `INTEGER` foi convertido inicialmente para `bigint`, preservando a faixa
  numerica do SQLite e mantendo flags `0/1` compativeis com o codigo atual.
- Chaves `INTEGER PRIMARY KEY AUTOINCREMENT` usam
  `GENERATED BY DEFAULT AS IDENTITY`. A opcao `BY DEFAULT` permitira importar
  os IDs existentes e reajustar as sequencias depois.
- Seis indices cobertos integralmente por uma chave primaria ou restricao
  unica nao foram reproduzidos:
  - `idx_esporo_visitas_kobo_uuid`;
  - `idx_ovitrampas_cal_eventos_data`;
  - `idx_ovi_lab_itens_lote`;
  - `idx_ovi_lab_lotes_evento`;
  - `idx_pe_codigo`;
  - `idx_resultado_lab_coleta_unico`.
- Os dois indices parciais foram preservados:
  - `idx_agentes_cpf_unico`;
  - `idx_esporo_buscas_legado`.

## Ferramentas

Gerar novamente o SQL de forma deterministica:

```powershell
python scripts\gerar_schema_postgresql.py
```

Consultar migracoes:

```powershell
python scripts\migrar_postgresql.py --database endemias_teste
```

Aplicar migracoes pendentes:

```powershell
python scripts\migrar_postgresql.py --database endemias_teste --aplicar
```

Comparar toda a estrutura:

```powershell
python scripts\comparar_schema_postgresql.py --database endemias_teste
```

O executor aplica todas as migracoes pendentes em uma transacao, usa bloqueio
consultivo contra execucoes simultaneas e recusa arquivos aplicados cujo
checksum tenha mudado.

Para aplicar em qualquer banco diferente de `endemias_teste`, o nome precisa
ser repetido explicitamente:

```powershell
python scripts\migrar_postgresql.py `
  --database NOME_DO_BANCO `
  --aplicar `
  --confirmar-banco NOME_DO_BANCO
```

Essa confirmacao foi usada nos ensaios explicitamente autorizados e
documentados em `endemias_migracao` e no banco final `endemias`.

## Etapa de carga concluida

O copiador SQLite para PostgreSQL foi criado e executado. Ele usa ordem de
dependencias, preserva IDs, converte marcadores temporais invalidos, reajusta
identidades e compara contagens e checksums antes do `COMMIT`.

A camada dual, o ensaio integrado, o restore descartavel, a carga final e a
ativacao da tarefa `SYSTEM` foram concluidos. O esquema oficial PostgreSQL foi
validado com 59 tabelas, 154.250 registros e 34 identidades alinhadas.
